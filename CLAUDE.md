# CLAUDE.md - PowerTrader AI

## 1. Project Overview

**PowerTrader AI** is a local, multi-process algorithmic cryptocurrency trading system written entirely in Python. It uses a proprietary "Memory-based" pattern-matching algorithm — **not a traditional neural net** (the name is a misnomer) — that stores historical OHLCV patterns as text files and matches current market states against them to generate Dollar-Cost Averaging (DCA) buy/sell signals (0–7 intensity scale). Market data comes from KuCoin; order execution runs against the Robinhood Crypto API, signed with Ed25519 cryptography. A Tkinter-based GUI (`pt_hub.py`) acts as the central orchestrator, managing three independent subprocesses (`thinker`, `trader`, `trainer`) that communicate exclusively through file-based IPC. A complete backtesting system was added in late December 2025, adding a replay engine (`pt_replay.py`), incremental walk-forward trainer, and analytics suite (`pt_analyze.py`).

## 4. Architecture & IPC Patterns

### Live Trading

```
pt_hub.py (GUI)
  ├─subprocess──► pt_thinker.py  ──[long_dca_signal.txt / short_dca_signal.txt]──► pt_trader.py
  │               │ reads KuCoin OHLCV                                               │ signs+sends to Robinhood
  │               └──[runner_ready.json, low/high_bound_prices.html]──► hub           └──[trader_status.json, trade_history.jsonl]──► hub
  └─subprocess──► pt_trainer.py  ──[memories_*.txt, memory_weights_*.txt]──► thinker
```

### Backtesting (Replay Mode)

```
pt_replay.py (orchestrator)
  ├─ warm_cache() ──► backtest_cache/ (KuCoin OHLCV JSON)
  ├─subprocess──► pt_thinker.py --replay  (reads cached candles, reads replay_data/backtest_state.json)
  ├─subprocess──► pt_trader.py  --replay  (simulated fills → replay_data/sim_orders.jsonl)
  └─ advance_time_atomic() ──► replay_data/backtest_state.json (sequence-numbered, atomic)
                                        │
                                        ▼
                               pt_analyze.py  ──► analytics_report.html
```

### Key IPC Files

| File | Direction | Content |
|---|---|---|
| `long_dca_signal.txt` / `short_dca_signal.txt` | Thinker → Trader | Integer 0–7 (DCA intensity) |
| `hub_data/trader_status.json` | Trader → Hub | Real-time account/position snapshot |
| `hub_data/trade_history.jsonl` | Trader → Hub | Append-only trade log |
| `hub_data/pnl_ledger.json` | Trader → Hub | Cumulative realized PnL |
| `low_bound_prices.html` / `high_bound_prices.html` | Thinker → Hub | Predicted price levels |
| `hub_data/runner_ready.json` | Thinker → Hub | Startup readiness gate |
| `replay_data/backtest_state.json` | Replay → Thinker+Trader | Atomic replay tick (sequence + prices) |

### Memory Model Details

- **Patterns** stored as `~`-delimited strings in `memories_{tf}.txt`
- **Scores** in `memory_weights_{tf}.txt`, `memory_weights_high_{tf}.txt`, `memory_weights_low_{tf}.txt`
- **Seven timeframes:** `1hour`, `2hour`, `4hour`, `8hour`, `12hour`, `1day`, `1week`
- **DCA signal:** integer 0–7; level ≥ 3 triggers a trade entry in the trader (configurable)
- **Training freshness gate:** `trainer_last_training_time.txt` per coin folder; thinker and hub both reject stale models (> 14 days)

## 5. Core Commands

```bash
# Run full system (main entry point)

  --start-date 2024-01-01 \
  --end-date 2024-06-01 \

  --start-date 2024-01-01 \
  --end-date 2024-06-01 \
  --coins BTC \
  --speed 10.0 \
  --output-dir backtest_results/my_backtest

python pt_analyze.py backtest_results/my_backtest

python -m unittest discover -s tests    # all tests
python -m unittest tests.test_backtest_integration
python -m unittest tests.test_e2e_smoke
python -m unittest tests.test_walk_forward
python -m unittest tests.test_performance   # slow — 6-month benchmark
```

## 6. Coding Standards & Best Practices

### File I/O (Critical) — Atomic Writes

**NEVER write JSON state files directly.** Write to `filename.json.tmp`, then `os.replace()`:

```python
def _atomic_write_json(path, data):
    tmp = f"{path}.tmp"
    with open(tmp, "w") as f:
        json.dump(data, f, indent=2)
    os.replace(tmp, path)
```

The same pattern applies to plain-text files (memory/weight files):

```python
def _atomic_write_text(path, text):
    tmp = path + ".tmp"
    with open(tmp, "w+", encoding="utf-8") as f:
        f.write(text)
    os.replace(tmp, path)
```

### Indentation — Critical Gotcha

The codebase has a **split indentation style**:

| Files | Style |
|---|---|
| `pt_thinker.py`, `pt_trader.py`, `pt_trainer.py` | **Hard tabs** (original developer uploads) |
| `pt_hub.py`, `pt_replay.py`, `pt_analyze.py`, `pt_incremental_trainer.py` | **4 spaces** |

Python 3 raises `TabError` if you mix them within a single file. **Always match the existing style of the file you are editing.**

### Other Patterns

- **Global state at module level** in `pt_trainer.py` and `pt_thinker.py` (dozens of globals: `starting_amount`, `profit_list`, `upordown`, etc.) — original developer style, do not refactor without understanding full impact.
- **Bare `except:`** used heavily in trainer/thinker for resilience. New code should use explicit exception types.
- **`os.chdir()` to coin folder** in `pt_thinker.py`'s `init_coin()` — works because thinker is a single-threaded subprocess. Always call `os.chdir(BASE_DIR)` after `init_coin()`. **Never add threading to thinker without removing this pattern first.**
- **`vprint()` pattern** — debug-only output behind a `VERBOSE` flag.
- **`PrintException()`** — custom traceback printer used in original trading code. New code uses `BacktestLogger` for structured JSON logging.
- **No type annotations** in original code; added in the backtesting phase.
- **Settings hot-reload** via mtime-cached `_load_gui_settings()`.
- **GUI refresh** — chart refreshes are throttled inside `pt_hub.py`'s update loop to avoid UI freeze. Preserve this when adding new panels.

## 7. Gotchas & Risks

### Critical

1. **`r_key.txt` / `r_secret.txt` must exist before importing `pt_trader.py`** — module-level code reads them and calls `raise SystemExit(1)` if missing. Any test that imports from `pt_trader.py` will fail without these files.

2. **`DEFAULT_SETTINGS` in `pt_hub.py:274` hardcodes a Windows path** (`"main_neural_dir": r"C:\PowerTrader_AI"`). Users on a fresh install must set this in Settings on first run. This project is Windows-only for now.

3. **KuCoin candle index order is non-standard:** `[timestamp, open, close, high, low, volume, turnover]` — index 2 is `close`, index 3 is `high`, index 4 is `low`. The backtesting code normalizes to named dicts; thinker/trainer parse them as raw strings.

4. **Memory files use custom delimiters, not JSON.** Patterns use `~` as separator; weights use space. Loading: `.split('~')` and `.split(' ')`. Partial writes silently produce empty pattern lists — always use `_atomic_write_text()`.

5. **Tab vs. space split** — see Indentation section above.

### Moderate

6. **No file locking on signal files.** `long_dca_signal.txt` / `short_dca_signal.txt` are written by thinker and read by trader without locking or atomic writes. Content is a small integer so truncation risk is low, but real.

7. **`psutil` subprocess monitoring** — if a subprocess crashes and the PID is reused by the OS before the hub notices, the hub may think the process is still alive and silently stop trading.

8. **`trade_history.jsonl` linear scan at startup** — DCA rate-limit state is seeded by scanning the full history file. Will slow startup as the file grows.

### Performance

9. **`_memory_cache` dict** in thinker/trainer caches memory/weight files in RAM keyed by timeframe (not coin). Multi-coin runs share this cache — be careful with path assumptions if refactoring.

10. **Backtesting target:** 6-month backtest should complete in < 10 minutes at 10× speed, using < 2 GB RAM and < 500 MB cache per coin.
